# 2026-09-10 — Dual-agent concurrency bench (32k, parallel 2, kv-unified)

## Config under test

```
-c 32768 --parallel 2 --kv-unified --cache-ram 8192 --cache-reuse 256
--cache-prompt --slot-save-path ...  (slot-save flaky with kv-unified, known)
--spec-type draft-mtp --spec-draft-n-max 3
--temp 0.6 --top-p 0.95 --top-k 20 --min-p 0.05 (server default; bench omits override)
```
Model: Qwen3.8-27B-GSQ-RCO-IQ3_XXS-mtp.gguf (10 GB weights)

Script: `dual_agent_bench.py` — two simulated agents (ALPHA/Python, BETA/JS) with distinct
stable system prompts (~133/137 tokens), synchronized concurrent turns.

## Results

| Phase | A t/s | B t/s | Aggregate | Cache evidence |
|---|---|---|---|---|
| 1. Single-stream baseline | 22.2 | — | 22.2 | cache_n 0 (fresh) |
| 2. Cold (first turn each) | 14.5 | 16.1 | 17.4 | A hit 133 (from baseline), B prefilled 156 |
| 3. Warm (2nd turn each) | 16.3 | 15.6 | 24.1 | **both prefixes hit**: A 133/152, B 137/154 — only deltas prefilled |
| 4. Sustained (400 tok each) | 13.5 | 13.2 | 20.1 | prefixes still cached |

MTP under concurrency: **78.6%** acceptance (243/309) — spec decode works batched.

## Findings

1. **Dual-prefix cache VERIFIED** — both agents' system prompts cached simultaneously;
   warm turns prefill only the delta (~17–22 tokens vs 150+ cold). Agent-switch thrash is gone.
2. **Aggregate throughput ≈ single-stream** (20–24 vs 22.2 tok/s): dense-27B batching is
   throughput-neutral (weights-bandwidth-bound), NOT superlinear.
3. **Per-stream cost of concurrency: ~40%** (13–16 vs 22 t/s each) — but wall-clock for two
   jobs is ~1.7× better than serial (7.6 s for both vs ~13 s serial).
4. 32k switch recovered single-stream speed (22.2 here vs 16.6–20.4 probes at 64k overflow).

## Verdict

Keep `-c 32768 --parallel 2 --kv-unified`. Optimal for the two-agent workflow:
cache thrash eliminated, wall-clock for parallel work 1.7× better, aggregate unchanged.
If a single long generation matters more than parallel latency, agents still serialize fine
on one slot — no config change needed.

## 2026-09-11 — 0.87.1 + draft-n-max 4 + 64k/parallel-1 (SINGLE slot): new best

Config: `-c 65536 --parallel 1` (no kv-unified), `--spec-draft-n-max 4`, engine 0.87.1,
`--cache-ram 8192` (cache-idle-slots active). NOT the 32k/parallel-2 config.

| Phase | A t/s | B t/s | Aggregate | vs 32k/p2/draft3 reference |
|---|---|---|---|---|
| Single baseline | **25.3** | — | 25.3 | 22.3 (+13.5%) |
| Cold | 27.6 | 25.8 | 19.9 | ~same aggregate |
| Warm | 27.5 | 27.1 | 24.4 | ~same aggregate |
| Sustained | 23.2 | 24.6 | 20.4 | ~same aggregate |

MTP acceptance **80.1%** (317/396 at depth 4 vs 82.1% at depth 3 — rate dips, tokens/step up).

### Findings
1. **draft-n-max 4 WINS**: +13.5% single-stream (25.3 vs 22.3). The 3-tuning was
   engine-generation-specific; on 0.87.1, deeper drafts win despite the acceptance dip.
2. **Dual-prefix caching works on ONE slot** via `--cache-ram` restore: A(133)+B(137)
   cached simultaneously — evicted slot prefixes are restored from the RAM cache on
   alternation. parallel-2 is not required for the no-thrash property.
3. **64k on 0.87.1 parallel-1 shows NO spill signature** (25–27 t/s) where 0.87.0
   measured 16.6–20.4. Either the engine improved or parallel-1 compute buffers are
   leaner. VRAM model (10+4.9+1.5=16.4 vs ~15 usable) says it shouldn't fit — watch
   for halved t/s on LONG (50k+) prompts; that would be the spill appearing late.
4. Aggregate throughput unchanged (~20–24 tok/s) — batching still weights-neutral;
   per-stream latency is where draft-4 pays off.
